# 局中人：AI 叙事副本与剧本杀

先在剧本库选择故事，再扮演其中一名角色，其余角色由 AI 陪玩。你也拥有秘密、人际关系、私人线索和个人目标，可以选择凶手角色，隐瞒经历、寻找盟友或引导讨论。角色私聊、公聊和投票理由都通过本机 traex 调用真实模型实时生成，没有预设角色台词。

## 首个规则怪谈副本

《第七夜：夜班病院》已接入故事库。扮演为寻找妹妹混入病院的许舟，和护士长、老病人、维修护工、广播声音及找到的妹妹交涉。这个副本没有凶手选择与投票；通关由实际行动和固定世界状态判断。内容见 [night_ward.json](backend/scripts/night_ward.json)；早期 [副本设计](night_ward_design.html) 保留了原始方案，当前玩法以代码和下述规则为准。

- 本局随机选择两种病房与接线布局之一，重开重新抽取。原始档案、床边腕带和接线标签对应本轮布局，提前不会返回真实布局。
- 从23:00开始，调查、行动与交涉进入可停留的现场：实际查看物件才获得对应线索，同一现场能连续追问和私下出示材料，结束时统一推进30分钟。部分独自处理的选择额外消耗30分钟，取消行动也会扣本次现场的时间。阅读与公开线索免费，持工牌正式离开也不耗时。
- 01:00熄灯，02:00与03:30巡查。护士站或同时恢复供电、清除残片的楼层安全；其他地点会进入巡查险情，可多花半小时退回护士站、主动消耗护栏或借正在诱导的广播引开它。屏息躲藏仍留下异常，迎面硬闯留下更多异常。
- 合错回路、循声开门及强闯出口都有独立险情和收场选择，后果由实际选择决定。三次异常失败。05:00出口开启，07:00仍未离开则失败。危险开门需要确认和当前版本；现场选择也校验版本与现场ID，重复请求不会再次执行。
- 现场交涉由对应人物参与，替代原来的机械轮换公开提醒。沈青可交钥匙，陆闻可答应压住隔离箱，许宁可回答童年问答或松开床栏，这些模型选择真实解锁对应操作。人物可以拒绝，玩家可以继续解释、对质或选择花时间独自处理。
- 场景中央可自由描述行动。模型理解你是在询问、尝试还是明确动手，程序从当前真实物件与规则允许的动作中执行；不能用一句话生成装备、补出物证或跳过身份核验。附近物件按钮收在展开栏中，不提供推荐路线。观察、贴门听和检查身体能得到具体现场反馈；原地等待真实推进时间，捂住广播会切断当前诱导，大喊或动手威逼会引来需要应对的巡查。
- 进入现场、翻物件及执行行动会触发在场人物主动接话，和玩家说的话按顺序留在现场记录。人物只得到自己亲眼看见的行为、自己的私聊和被公开的材料；其他房间的主持记录与世界私密状态不会自动送给它。动手威逼会留下关系记忆，陆闻或许宁可能收回当前配合。异常以手腕与影子的变化反馈。
- 床边腕带只证明号码与颜色。取得登记和腕带后，可以先在床边和妹妹谈恐惧、私下问童年问题；她当次亲口答对的记忆会保留，进入核验后可直接核对三项，无需再问一遍。核验、争取她的配合与实际牵她离床分别执行。通关有“独自归来”“带她回家”“把名字带出黑夜”三档成功结局，失败也有规则与人物复盘。
- 实际救出的许宁会随行，在当前位置找她交谈。在场人物会看到她随行，以及现场已经完成的清理和供电；险情中的退路仍由实际应对决定。残片已封装而安全灯未恢复时，巡查仍会到来，现场会分别说明这两项事实。

AI 失败时，现场与已经查看的材料保留；失败的这句话、出示材料与人物效果都不提交，输入保留供重试。主动回应失败可重听，也可先继续行动，已执行的物理后果不会重复扣时。现场内交谈不额外扣时。私下出示的材料只交给收件人，其他人物需要公开材料才能知道。妹妹知道自己与哥哥的童年约定，其他人物不会自动获得它。直接调用旧 `/api/question` 而未先进入现场的私聊仍按成功一次30分钟处理。

自由行动一次只处理一项主要动作。“去档案室查登记并拿走”先到场，不会自动翻查：现场会明确写出已到达、登记未翻查或拿取，并保留模型对仍未处理部分的简短自然说明，不添加实现标签。在场人物会收到玩家到场时说明的来意，但不会因此自动同意、交付材料或知道别人的私聊。

提交自由行动后先显示“正在理解，尚未执行”；服务器返回后立即显示本次现场结果，再单独等待在场人物斟酌。自由输入中的请求/询问也先完成动作理解，再交给本人生成回复，不当成玩家已经动手。每段等待满10秒会说明请求仍在处理中、不是已取消；此时可读已取得材料与已有谈话、试听已有发言，但不能改变现场或重复提交。失败后“接续人物回复”只接续原来的回应，不重新执行物理动作或扣时；没有提供取消仍在处理请求的功能。这些是实现行为，真实模型等待时长与页面验收需另行记录。

副本采用场景界面：护士站、档案室、配电房、两间病房与出口分别显示生成的写实背景，当前地点有可点击的调查点；行动描述与现场说话是主要入口，附近物件放在可展开栏中，调查路线由玩家自行决定。新取得的材料直接展开，读完收进随身线索。楼层图可选择地点并执行调查或当地行动，选地图本身不移动、不耗时。人物回应和私下交谈按顺序留在场景里，搭配人物图；广播只显示扬声器，找到床边本人后显示女孩的形象，是否已核验单独标明。图片通过生成服务加载，需要网络；素材是氛围插画，不代替腕带、回路等随机线索的文字真值。场景有低声灯鸣，险情中有逐渐接近的脚步，和结局演出共用音效开关，浏览器第一次点击后才可播放。

读取材料不自动完成目标，核验和救助仍需执行行动。值班须知、完整材料与夜班记录随时从场景上方打开；玩家依据现场、材料和人物口供决定调查、避险和离开的时机。

实际失败后播放约4.7秒的结局演出：异常达到上限时，无脸巡查员逼近镜头、突然冲上前，画面震动后切黑；07:00超时则是出口闭合、灯光熄灭。演出不额外扣时，完成后进入原有复盘。支持按钮或Esc跳过、独立音效开关，以及在失败结局“重看最后一幕”；刷新或重新打开已失败的局不会自动重播。音效使用浏览器Web Audio合成短促冲击声，播放需要浏览器允许音频；系统减少动态效果设置会取消快速扑近与震动，保留渐暗和结局文字。

后端按 `gameType` 选择 `Game` 或 `DungeonGame`，前端选择对应工作台。`dungeon_rules.py` 校验布局、线索引用、前置条件和允许效果；`dungeon.py` 执行医院生存规则。当前支持这套显式实现的医院机制，新的副本类型仍需要增加自己的规则执行与校验，不能只靠模型生成。

规则验证：`python3 -m unittest backend.test_dungeon -v`。25 项自动检查覆盖双布局结局、物件调查与补查、连续交涉、人物配合解锁、私密出示原子性、妹妹问答与安抚、违规分支、巡查应对与护栏取舍、错误回路纠正、出口边界、版本与重置隔离和旧剧本启动。检查使用确定性模型替身，实际模型质量需另行试玩。

剧本库会显示每个故事的当前角色与阶段，点击“继续这一局”接回进度。每个剧本的游戏状态、手牌、投票、NPC 记忆和对话分别保存，切换剧本不会清空另一局。“重开本剧本”只清空当前故事。状态同时保存在后端内存与实例的存档目录中，重启后端会从该目录恢复。

前端使用 React 18 + Vite，页面拆为剧本库、选角、游戏布局、读本、私聊、搜证、公开讨论及线索组件。`useGame` 统一处理 HTTP 操作与 AI 等待队列，`useNarration` 管理逐字显示和语音。前端显示文案、席位数量和搜证次数从当前剧本状态读取。

语音使用设备提供的中文 `speechSynthesis` 音色，为三个可玩剧本配置人物音色偏好、语速与轻微音高区别，并结合角色当前情绪微调节奏。中文声音异步加载后自动更新，优先匹配人物及自然/增强音色；设备只有一种中文声音时，无法凭空生成不同音色。页面顶部“人物声音”可为各角色手动选声音、调整语速，设置按剧本与人物保存在当前浏览器；“试听最近发言”只重播该人物真实生成过的发言，无发言时禁用。开启语音后按句朗读并留停顿，公聊多人的语音按顺序播放，不会被下一位角色的新回答截断；关闭语音、停止朗读或返回剧本库会清空播放队列。对白提示要求自然口语，避免书面总结、舞台指示及重复套话。浏览器朗读的情绪表现有限，这些调节不等于真人配音，也没有接入需要额外 API Key 的语音服务。

## 怎么玩

1. **选本、选角与读本**：在剧本库打开故事，领取任一角色的私人剧本，阅读经历、秘密、关系和个人目标。
2. **双向私聊**：你可以找角色交换信息、试探或争取合作；角色也会根据自己的目标、关系和当前局势主动邀请你。接受后由对方先开口，可以婉拒或稍后回复。各自的对话记录和输入草稿独立保留。
3. **搜证**：地点、总次数、阶段配额及开放时机由剧本决定。旧四人本最多搜三个地点；庄园本首轮两个，公聊时补查两个。线索进入你的手牌，其他人也拥有各自的线索。
4. **公聊**：AI 轮流主动发言，后发言者会回应前面的讨论。你可以公开手牌、发言或听他们继续聊，也可以返回私聊。公开线索对全桌可见。
5. **秘密指认**：提交你的一票，AI 分别依据自己的经历、记忆和公开材料投票，不能读取其他人的票。
6. **复盘**：所有票同时揭晓；显示唯一最高票指认（平票则没有唯一指认）、固定案件真相、完整时间线及你的个人目标完成情况。增加全人物剧情复盘：逐人物或一键展开背景、秘密、个人经历、角色视角的人物关系、原始目标与角色本关联线索，明确标记凶手及玩家角色；还可展开全部线索，包括本局未发现的内容。复盘使用固定剧本资料，不把 AI 即兴口供或记忆当成既定事实；关联线索不代表本局实际取得，复盘展示不会改变手牌或公开线索。全部人物的私人资料与全线索详情仅在最终 `reveal` 阶段随 `result.characters`、`result.evidence` 返回，其他阶段仍保持隔离。表演与开放叙事目标标为“自行回顾”，不伪装成系统已经判定。

读本页先直接展示共同背景和已公开时间线，再展示个人经历与秘密。剧本可提供可选的公共 `opening` 正文，未提供时使用 `summary`；这份公共开场也进入 NPC 可见上下文。庄园本说明降灵会的目的、主持人与死者关系、饮杯—断电—发现死亡的经过以及命案后开始游戏的时点；奥斯卡个人本另外说明自己的恶作剧和私人目击。公共开场不揭露断电实施者、仪式骗局、毒物或凶手。

AI 调用失败时，已完成的发言保留，当前角色仍在等待队列中。点击“继续 AI 发言”或“继续指认”即可接上。首次公聊及每一轮追加公聊会依次调用同桌其余角色，8人本需要七次推理。

允许 `initiative` 的阶段，页面在交流间隙自动让本阶段待判断的 AI 同时判断是否主动私聊，每个角色每阶段最多成功判断一次；旧六幕模式是第二至第四幕。一批可以产生多条邀约，你可以分别接受、婉拒或稍后回复；有未回复邀约时暂停自动启动下一批。角色可以选择暂不联系，不保证每轮都有人找你；判断和开场都由真实模型生成。邀约本身不交付线索，接受并成功生成开场后才可能私下收到线索。婉拒、暂缓和邀约状态只提供给对应角色，不进入公聊；进入不允许私聊的阶段，未处理邀约过期。离开游戏页面会暂停自动启动判断，返回后接上；一批中成功的结果保留，失败角色仍在队列中，点击“重试邀约判断”只重试这些角色，不会自动无限重试。生成期间本局状态若发生变化，整批旧结果不写回。

## 配置与启动

后端使用 Python 3 标准库，无须安装模型 SDK。默认调用本机 `traex`，使用其已登录身份及 `Doubao-Seed-2.1-Turbo` 模型。

### traex（默认）

```sh
traex login status
traex models --json
npm --prefix frontend install
npm --prefix frontend run build
NPC_AI_PROVIDER=traex python3 -u backend/server.py
```

如果尚未登录，先执行 `traex login`。可以设置以下环境变量覆盖默认值：

```sh
export NPC_AI_PROVIDER=traex
export NPC_AI_TRAEX_COMMAND="/Users/bytedance/.local/bin/traex"
export NPC_AI_MODEL="Doubao-Seed-2.1-Turbo"
export NPC_AI_TIMEOUT=120
```

模型 ID 使用 `traex models --json` 中的 `config_name`（没有时使用 `name`）。后端启动时预热一个 `traex app-server --listen stdio://` 子进程，之后按剧本和角色分配独立的常驻子进程，通过各自的 JSON-RPC 连接通信。每个 AI 角色第一次发言时创建独立 `thread`，之后私聊、公聊和投票复用该线程，并以 JSON Schema 约束最终回答。其他角色的私聊不会进入这个线程。多角色并发会增加本机进程数和内存占用。

常驻会话自动保留已完成的对话，不需要每轮重新启动 CLI 或重复发送全部历史。后端仍保存角色的记忆摘要、私聊与公开讨论，作为游戏状态和恢复依据；每轮发送最新角色可见上下文。后端用唯一响应 ID 确认上一轮是否实际保存，拒绝复用含有未提交回答的线程。回答结构无效、超时或进程退出后会清理对应角色的服务状态；下一次请求根据后端已保存的记忆重建会话，不中断其他角色的连接。不同剧本使用独立连接；同一剧本重开后，角色下一次推理会根据新的游戏 ID 重建服务及线程。游戏进度、随机布局、当前现场、线索和私人记忆在每次操作后原子写入 `.saves/<scriptId>.json`，后端重启会恢复，CLI角色线程按已保存记忆重新建立。该目录已加入Git忽略；重开只覆盖对应剧本存档。

`NPC_SAVE_DIR` 可指定实例独立的存档目录，未设置或为空时仍默认项目根目录的 `.saves`。绝对路径直接使用，`~` 会展开，相对路径以项目根目录为基准，与启动终端的工作目录无关。后端启动会打印实际存档目录。另开评测实例时，须同时使用未占用的端口和全新独立目录；只换端口仍会共享存档，不能用于隔离试玩。该配置不改变模型权限、登录身份或现有服务。

隔离运行示例：从项目根目录执行。以下沿用本次真实试玩成功的启动结构：在 `/tmp` 中用完整 Python.app 可执行文件启动独立服务器。解释器路径对应本机 Homebrew Python3.11.14，其他机器须换成实际安装路径；端口8003须未被占用。每次生成新的存档目录，不加载原局。

```sh
PROJECT_ROOT="$PWD"
REVIEW_SAVE_DIR="$(mktemp -d /tmp/night-ward-saves.XXXXXX)"
(
  cd /tmp
  NPC_AI_PROVIDER=traex NPC_PORT=8003 NPC_SAVE_DIR="$REVIEW_SAVE_DIR" \
    PYTHONPATH="$PROJECT_ROOT" PYTHONDONTWRITEBYTECODE=1 \
    /opt/homebrew/Cellar/python@3.11/3.11.14_1/Frameworks/Python.framework/Versions/3.11/Resources/Python.app/Contents/MacOS/Python -B -u -c '
import os
from http.server import ThreadingHTTPServer

from backend.npc_ai import start_ai, stop_ai
http = ThreadingHTTPServer(("127.0.0.1", int(os.environ["NPC_PORT"])), server.RequestHandler)
try:
    start_ai()
    print(f"Preview: http://127.0.0.1:{http.server_port}; saves: {server.STORE.directory}")
    http.serve_forever()
except KeyboardInterrupt:
    pass
finally:
    http.server_close()
    stop_ai()

```

打开 `http://127.0.0.1:8003`，核对终端打印的独立存档目录。同结构的8002和新版8003隔离实例已经得到真实行动理解与NPC回应；真实复玩、页面检查及各自的证据边界见 [评测记录](product_evaluation.md) 和 [开发交付](product_iteration.md)。`GET /api/ai-status` 的 `ready=true` 只代表握手，新实例仍需实际交互确认推理成功。本次环境中的普通 `-m backend.server` 启动仍遭权限拒绝，没有查清其原因；不能把上述实例成功当作所有启动方式已修复。运行环境权限失败不等于缺少 API Key，也不代表所有服务不可用；不要修改全局权限、沙盒或复制凭证来规避。

调用限定为纯角色对话，禁用工具、插件和项目说明加载，拒绝协议中的工具、权限和交互输入请求；不会自动授权模型操作文件或执行命令。CLI 的 SQLite 状态及日志写在本服务的临时目录，登录身份仍使用本机配置；关闭后端时清理子进程与临时目录。当前实现依赖 CLI 的实验性 app-server 协议，更换 CLI 版本后需要验证兼容性。

不需要单独设置 API Key；模型推理通常仍由 TRAE 的远端服务完成，需要网络及可用账号额度。

常驻进程省去了每轮启动 CLI 的成本，模型生成仍需等待网络服务。默认单轮超时为 120 秒，可以通过 `NPC_AI_TIMEOUT` 调整。不同角色的邀约判断并发执行，等待时间主要由本批最慢的角色决定；同一角色的生成、校验和格式重试仍串行，避免上下文交叉。公聊保持轮流发言，让后发言者能回应前面的讨论。

之前每轮启动 `traex exec` 的方案在受限后台环境报过 `failed to initialize in-process app-server client: Permission denied (os error 13)`。切换常驻服务不会放宽该环境的权限；启动失败时仍会明确报错。可以访问 `GET /api/ai-status` 检查 `running`、`ready`、进程列表 `pids`、创建过的进程数及角色会话数；`pid` 保留为首个运行进程，兼容旧接口。`ready=true` 仅代表至少一个连接协议握手成功，真实推理成功需另行验证。

最终回答优先取协议标记为 `final_answer` 的消息。解析兼容纯 JSON、BOM 和单个 JSON Markdown 代码块（可带说明文字）；截断或多代码块回答仍会拒绝保存。解析失败时，后端终端记录字符数、代码块数量及 JSON 错误行列，不打印角色秘密或模型思考内容；`/api/ai-status` 的 `lastError` 保留本次错误。修改后端代码后，需要在启动它的终端按 Ctrl+C，再执行启动命令加载修改。

JSON 或结构校验失败时，在同一个角色线程中最多让模型重新生成一次，仍须通过全部线索归属和投票校验才保存。两次调用共用 `NPC_AI_TIMEOUT` 时限，权限、网络和超时失败不触发格式重试。`/api/ai-status` 的 `formatRetries` 记录格式重试次数，`lastFormatError` 保存最近错误的角色 ID、阶段、字符数和解析位置，不包含回答原文；重试后成功时这些诊断仍保留。

浏览器打开 `http://127.0.0.1:8000`。若修改了前端，在 `frontend` 目录执行 `npm install` 和 `npm run build`，然后刷新。

HTTP 模式的 API Key 仅由后端环境变量读取，不发送到前端。未登录、配置缺失、网络失败或模型返回无效结构时，界面显示错误，本轮不会增加对话、修改记忆或解锁证据。

## 角色与状态

- 每个 AI 角色仅收到公共背景、自己的私人剧本与手牌、全桌公开线索、公聊记录、自己与玩家的私聊及独立记忆。玩家的秘密和手牌、其他角色的私人档案和私聊、其他人的投票不会放入上下文。
- 凶手档案包含自己的作案过程；无辜角色只知道自己的行为与目击。模型应维持既有口供，并根据实际对质选择隐瞒、辩解或承认。
- 模型输出角色发言、情绪、更新记忆、愿意分享的证据 ID 和投票选择。后端校验证据归属；私聊分享仅将线索交给玩家，公聊分享才公开给全桌。主持流程、搜证材料和案件真相固定。
- 重复提及已经取得的物证不会重复解锁，也不会使整轮对话失败。适配器兼容纯 JSON 和完整的 Markdown JSON 代码块，其他无效输出仍拒绝保存。
- 每个剧本拥有独立的进程内游戏状态；所有浏览器仍共享同一剧本的一局，不提供多用户隔离。模型调用使用所属剧本的状态快照，调用期间该局发生重置或另一轮对话提交时，旧回答返回 409，不覆盖新状态。操作请求始终携带 `scriptId`，避免切换界面后误操作另一剧本。

## 添加剧本

所有故事在 `backend/scripts/*.json` 中，启动时自动加载，不需要修改 React 页面或游戏流程代码。复制一个现有 JSON，修改唯一 `id`、公开简介、角色、线索、地点、时间线和真相，再重启后端即可出现在剧本库。完整字段说明见 [剧本配置说明](backend/scripts/README.md)。

`backend/rules.py` 定义通用玩法：阶段配置、允许的操作、进入阶段时发放的线索和组合目标条件。`Game` 按配置执行；前端读取 `allowedActions`、`phaseKind`、`nextPhase`，不再把搜证、公聊、投票绑定到固定幕数。未配置 `mode` 的旧本自动使用原六幕模式；同一种基础操作可以在多个阶段开放。新特殊机制须显式实现并通过校验，未知动作会拒绝加载，不能用模型对话假装执行。

加载时校验重复 ID、凶手角色、线索引用、角色关系、目标条件、阶段规则及搜证次数，配置错误会指出文件并阻止启动。剧本库接口只返回公开元数据与进度，阶段里的私人发牌配置不会返回前端；角色秘密只在选角后返回给对应玩家，固定真相和完整时间线只在 `reveal` 阶段返回。

事实一致性和线索透露的合理性依赖模型遵守角色指令，结构校验并不能保证每句话都符合案情。更换模型后应进行多轮试玩，评估角色性格、抗诱导能力及对质节奏。

## HTTP 接口

`GET /api/scripts` 返回剧本库及公开进度；`GET /api/state?scriptId=last_letter` 读取指定剧本的玩家可见状态；`GET /api/ai-status` 读取常驻 AI 服务状态，不返回角色秘密或对话。以下操作均使用 `POST` 和 JSON 请求体，所有请求可带 `scriptId`，省略时默认 `rain_lock`，兼容原接口：

| 接口 | 请求体 | 用途 |
| --- | --- | --- |
| `/api/start` | `{"scriptId":"last_letter","roleId":"secretary"}` | 选角入局 |
| `/api/reset` | `{"scriptId":"last_letter"}` | 只清空指定剧本 |
| `/api/advance` | `{}` | 推进到剧本配置的下一阶段；秘密投票结束后自动进入复盘 |
| `/api/question` | `{"npcId":"guest","question":"…"}` | 独立私聊 |
| `/api/initiative` | `{"scriptId":"last_letter"}` | 并发判断当前阶段全部待判断角色的邀约 |
| `/api/invitation-response` | `{"scriptId":"last_letter","invitationId":"…","decision":"accept"}` | 接受、婉拒（`decline`）或暂缓（`later`）邀约 |
| `/api/search` | `{"locationId":"machine"}` | 搜索地点 |
| `/api/act` | `{"scriptId":"night_ward","actionId":"wait","version":3}` | 执行副本行动；危险操作还需 `confirm:true`，其他本返回409 |
| `/api/approach` | `{"scriptId":"night_ward","npcId":"head_nurse","version":3}` | 进入可连续对话的现场交涉 |
| `/api/choice` | `{"scriptId":"night_ward","encounterId":"…","choiceId":"journal","version":4}` | 查看物件或处理现场，版本必填 |
| `/api/scene-action` | `{"scriptId":"night_ward","message":"我贴着门板听动静","version":4}` | 理解自由行动，执行真实现场效果 |
| `/api/scene-turn` | `{"scriptId":"night_ward","cueId":"…"}` | 人物回应自己在场看到的行为，不额外扣时 |
| `/api/silence` | `{"scriptId":"night_ward","cueId":"…"}` | 暂不听这次回应，继续处理现场 |
| `/api/publish` | `{"evidenceId":"ledger"}` | 公开自己的手牌 |
| `/api/discuss` | `{"message":"…"}` | 玩家公聊并排下一轮 AI；空内容让 AI 继续 |
| `/api/ai-turn` | `{}` | 完成队列中一名角色的公聊或秘密投票 |
| `/api/vote` | `{"targetId":"boss_wife"}` | 提交玩家的秘密指认 |

`question`、`ai-turn` 及接受邀约返回 `{reply, state}`；副本 `question` 还接受 `evidenceIds`（实际持有、私下出示的材料）与 `version`。副本状态的 `encounter` 保存当前现场、已查看物件和可选操作。`scene-action` 返回动作理解/执行后的状态；若有 `sceneCue`，需另调用 `scene-turn` 获取人物回复。`sceneCue.kind=speech` 表示原话待本人回复，`reaction` 表示人物待回应已发生的现场结果；自由请求不会在第一段自动提交人物合作效果。`scene-turn` 返回 `{reply, speakerId, replyKey, state}`，成功后移除当前cue，失败可用同一cue重试。`initiative` 返回 `{invitations, errors, invitation, state}`，`invitations` 是本批新邀约，`errors` 包含失败角色的 `npcId`、`npcName` 和 `message`；兼容字段 `invitation` 是第一条新邀约，无则为 `null`。婉拒、暂缓和其他接口直接返回状态。NPC 开场记录包含 `initiator: "npc"`，`question` 为空，前端不会伪造玩家发言。秘密投票期间 `reply` 为 `null`，投票详情只在复盘的 `result` 中返回。状态还包含 `phaseId`、`phaseKind`、`allowedActions` 和公开的 `nextPhase`；按钮和接口都服从该剧本的规则。此 Demo 仅供单人本地试玩，不提供多人会话隔离。
